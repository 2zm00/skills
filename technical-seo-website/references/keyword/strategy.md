# SEO 키워드·메타타이틀 전략

페이지마다 "어떤 검색어를, 어느 시장에서, 이 페이지가 이길 수 있는가"를 숫자와 SERP로 판정하고 제목을 만든다. 추정하지 않는다. 숫자는 측정한 그대로 적는다.

## 실행 환경

경로는 모두 이 스킬 폴더 기준이다(`scripts/keyword/…`, `references/keyword/…`).

| 환경 | 이렇게 한다 |
|---|---|
| Aside (맥) | 전부 가능. 브라우저 단계(구글·네이버 SERP, 서치콘솔)는 `references/keyword/tool-recipes.md`의 REPL 코드. node가 안 잡히면 `~/.aside/runtime/bin/node` |
| Claude Code (터미널) | `node scripts/keyword/*.mjs` 실행. 검색량은 `scripts/keyword/volumes.mjs`(브라우저 없이 네이버·구글 한국·일본). 구글 SERP는 topaz `/api/serp`(한국·일본) 또는 웹 검색(국가 지정이 안 되므로 한계로 적음). 서치콘솔은 사용자가 실적 CSV를 내보내 준다 |
| Claude 앱 (claude.ai) | 외부 사이트 호출이 막힐 수 있다. 검색량 표·서치콘솔 CSV·SERP 캡처를 사용자에게 받아 판정과 제목 작성에 집중한다. 웹 검색 결과는 국가 지정이 안 되므로 참고로만 쓴다 |

## 0. 원칙 (사용자 규칙)

- 메타타이틀은 **페이지 역할 · 제목 키워드 · 검색량 · SERP · 노출 가능성**만으로 판단한다. 클라이언트가 요청하지 않은 브랜딩·사업 서사를 키워드 선택 근거로 끌어오지 않는다.
- 페이지가 실제로 다루는 것만 제목에 넣는다. 검색량이 커도 페이지가 다루지 않으면 콘텐츠(블로그·클립) 몫으로 넘긴다.
- **네이버와 구글 SERP를 둘 다 본다.** 하나만 봤으면 "어느 쪽을 안 봤는지"를 보고에 적는다.
- 모든 추천에 근거를 붙인다: "전에는 ~ 때문에 ~였고, 지금은 ~ 이유로 ~가 낫다".
- 클라이언트 의견은 **범위 필터**로 쓴다: 목표 시장, 제외 시장, 핵심 서비스, 지점·지역, 옛 브랜드명, 업종 규제, 금지어. (예: 예시피부과는 원장 요청으로 일본어·영어·대만 중국어를 우선하고 한국어 키워드는 부록으로만 다뤘다. 의견은 담당자를 거쳐 전달받았으므로 문서에 따옴표 인용으로 쓰지 않는다)

## 1. 입력 확인

1. 클라이언트 의견: 목표 시장·언어, 매출 비중이 큰 서비스, 지점 위치, 리브랜딩 이력(옛 이름·옛 도메인), 규제(의료법 등), 꼭 넣거나 빼야 할 단어.
2. 대상 페이지 목록과 현재 title·H1: 스크리밍프로그 Internal All CSV가 있으면 `scripts/audit/sf-summary.mjs`, 없으면 직접 읽는다.
3. 서치콘솔 접근 여부: 있으면 검색어·페이지·국가 표를 500행씩 받는다(`references/keyword/tool-recipes.md` §5).

## 2. 후보 키워드 만들기 (페이지당 10~25개)

- 페이지 역할에서: 서비스명, 지역+서비스(강남 울쎄라), 역명+서비스, 업종명(피부과·美容皮膚科·醫美), 수식어(가격·추천·후기·잘하는곳·料金·おすすめ·推薦·price).
- 서치콘솔에서: 그 페이지에 노출되는 검색어, 순위 4~20위·노출 많은 검색어.
- 경쟁사에서: SERP 상위 제목의 반복 단어.
- 붙여쓰기·띄어쓰기·표기 변형(ウルセラ/ウルセラ 韓国, 江南/江南(カンナム)), 옛 브랜드명.

## 3. 검색량 측정

기본: `node scripts/keyword/volumes.mjs --naver "강남 울쎄라,강남 리쥬란" --kr "강남 피부과" --jp "江南 美容クリニック" --out <작업폴더>` → `naver_vol.json`, `google_vol.json`(kw-table 입력 형식). 막히면 `references/keyword/tool-recipes.md` §1·§2 브라우저 방식.

| 시장 | 도구 | 비고 |
|---|---|---|
| 한국 네이버 | ma-pia.net 키워드 조회 | 붙여쓰기, 한 번에 100개, "0"은 10 미만으로 기록 |
| 한국·일본 구글 | keyword-analyzer-topaz `/api/keywords` | 정확히 같은 행만 사용. 다른 나라는 지원 안 함 |
| 대만·영어권 등 | 서치콘솔 노출수로 대리 판단 | 정확한 값이 필요하면 구글 키워드 플래너를 클라이언트에 요청 |

## 4. SERP 실측

- 구글: 시장마다 `googleSearch.search(q,{country,language})`(Aside 전용)로 상위 10개 도메인·제목·우리 순위를 저장. 30초당 6회 제한이 자동으로 걸린다. 한국 IP에서 국가·언어만 지정한 결과라는 한계를 보고에 적는다. AI 개요 여부가 필요하면 topaz `/api/serp`(한국·일본).
- 네이버: 첫 화면 블록 순서(광고·플레이스·클립·웹사이트·AI 브리핑), 우리 도메인이 **광고인지 자연 노출인지**, 웹사이트 블록 유무, 웹문서 탭(`&ssc=tab.web.all`) 상위.
- 저장: `tmp/serp_google.json`, `tmp/serp_naver.json` 형식으로 남겨 `scripts/keyword/serp-intent.mjs`, `scripts/keyword/kw-table.mjs`가 읽게 한다.

## 5. 판정 (`references/keyword/rules.md` R0~R13)

핵심만:
- **의도 분류**(R3): 상위 8개를 병원·업체 / 비교 플랫폼 / 커뮤니티·SNS / 미디어·블로그 / 공공·위키로 나눈다. 업체 직접 경쟁형이면 페이지 제목으로 진입 가능, 플랫폼·커뮤니티형이면 제목만으로는 약하고 플랫폼 등재·콘텐츠가 필요.
- **네이버 3천 규칙**(R4): 월 3,000 이하 + 민간 문서가 들어오는 자리면 제목 슬롯으로 노린다. 3,000 초과는 본문 힘으로 겨루는 키워드. 웹사이트 블록이 아예 없으면(로컬 의료 키워드에서 흔함) 홈페이지 제목은 레버가 아니라고 명시한다.
- **로컬 공식**(R10): 지역+서비스를 맨 앞에 (예: `강남울쎄라 | 강남역 울쎄라 프라임 | 지점명`).
- **해외 현지어**(R11): 번역하지 말고 현지 검색어로 쓴다 (リフティング 대신 リフトアップ, 江南 대신 江南(カンナム), 대만은 醫美).
- **옛 브랜드 잇기**(R12): 리브랜딩이면 旧エグザンプル / 舊Example Old처럼 병기.
- **규제**(R13): 의료는 'No.1·최고' 같은 최상급 금지, 가격은 페이지에 조건이 있을 때만.
- **길이**: `scripts/keyword/title-px.mjs`로 폭을 재서 561px(스크리밍프로그 기준) 안쪽으로.

## 6. 출력

`references/keyword/output-template.md` 형식:
1. 페이지별 표: 현재 → 제안(폭 px) / 키워드별 네이버·구글 검색량 / SERP 판정 / 서치콘솔 현재 순위 / 근거.
2. 시장별 전략 요약(이길 수 있는 키워드, 콘텐츠로 넘길 키워드, 제외 키워드와 이유).
3. 측정 한계(조회 못 한 시장, IP 한계, 날짜).
4. 바꾼 경우 이전 값 보관(`prev_title`).

## 제안서용 출력

제안서(`seo-proposal`)에 넣을 때는 대표 페이지 3~8개를 `titles.json`으로 저장한다: `[{page, now, nowPx, proposed, proposedPx, keyword, vol, why}]`. 현재 순위만 빠르게 볼 때는 `seo-quick-check` 스킬의 `scripts/serp-check.mjs`를 쓴다(설치되어 있을 때만. 없으면 `scripts/keyword/serp-intent.mjs`).

## 토큰 절약 (품질은 그대로)

- 검색량은 `scripts/keyword/volumes.mjs`로 받는다(브라우저 탭·스냅샷 없이 요약만 출력).
- SERP는 화면 스냅샷 대신 결과를 JSON으로 저장하고 `scripts/keyword/serp-intent.mjs`·`scripts/keyword/kw-table.mjs`가 만든 표만 읽는다. 원본 결과 목록을 채팅에 찍지 않는다.
- `references/keyword/rules.md`는 판정할 때 한 번, `tool-recipes.md`는 막힌 단계의 절만 읽는다.
- 서치콘솔 검색어는 500행을 파일로 저장하고 대상 페이지·키워드에 해당하는 행만 걸러 본다.

## 7. 실행 순서 요약

1. 입력·클라이언트 의견 정리 → 2. 후보 → 3. 검색량(`node scripts/keyword/volumes.mjs`) → 4. SERP(구글 시장별·네이버) → 5. `node scripts/keyword/serp-intent.mjs` → 6. `node scripts/keyword/kw-table.mjs`로 검색량·GSC·SERP 합치기 → 7. 규칙 적용·제목 작성 → 8. `node scripts/keyword/title-px.mjs`로 폭 확인 → 9. 표·근거로 보고.
