# 네이버 블로그 포커스 키워드 고르는 법 (공통 기준, 2026-11-08)

예시블로그A·예시컴퍼니·예시블로그B·예시블로그C 네이버 블로그 4곳이 같이 쓴다. 각 스킬에는 이 파일을 가리키는 한 줄만 둔다(규칙은 여기 한 곳에서만 고친다).

## 1. 기준
- 포커스 = 네이버 월간(PC+모바일, 마피아넷) **200~3,000**. 린트 K6가 3,000 초과는 ERROR, 200 미만은 WARN.
- 주제(헤드)는 몇만이어도 된다(2026-11-08 대표 지시 "메인 키워드가 몇만이면 미들테일·롱테일·관련검색어로 조사해서 검색량 맞춘 다음에 써도 된다"). 헤드는 front matter `head_keyword` 에 적고 본문·소제목·태그에 쓴다. 포커스로는 잡지 않는다.
- 근거(11/8 전수조사): 통합검색 1페이지에 뜬 6편은 모두 포커스 3,000 이하, 3,000 넘는 포커스 6편은 하나도 없었다.

## 2. 넓히기 (헤드가 3,000을 넘을 때)
1. `node <technical-seo-website 스킬 폴더>/scripts/keyword/kw-expand.mjs "<헤드>" --max 45` → 자동완성 2단계 + 질문형 접미어(방법·비용·가격·뜻·차이·추천·신청·조건·기간·서류·무료) 후보.
2. 브라우저 검색 결과의 "관련 검색어"(스크립트로는 안 잡힘, snapshot 으로 읽기)와 줄임말·다른 이름도 직접 넣는다. 예: 청년창업사관학교(5,470) → 자동완성은 전부 200 미만인데 줄임말 "청창사"가 1,370.
3. 후보 전부를 마피아넷(ma-pia.net/keyword/keyword.php, 100개씩)으로 잰다. 표의 열: 빈칸, 번호, 키워드, PC, 모바일, **합계(5번째 td 인덱스 5)**, 입찰가, **경쟁도(인덱스 7)**. 띄어쓰기 차이는 같은 값으로 나온다.

## 3. 고르는 기준 (여러 각도로 보고, 숫자만으로 정하지 않는다)
| 각도 | 볼 것 | 예 |
|---|---|---|
| 검색량 | 200~3,000 | 클로드 코드(27,460) → 클로드 코드 요금제 2,840 / 설치 630 |
| 의도 일치 | 글이 실제로 답하는 질문인가. 제목·첫 문단이 그 질문에 바로 답할 수 있나 | "설치부터 요금까지" 글이면 요금제 또는 설치 중 글의 중심 하나 |
| 헤드 포함 | 롱테일 안에 헤드 단어가 들어 있으면 헤드 노출도 같이 쌓인다. 같은 값이면 헤드를 품은 쪽 | 사업자등록증 발급방법(1,910) > 사업자등록증 사본(1,110) |
| 검색 결과 모양 | 통합검색에 블로그 글 자리(인기글·스마트블록)가 있나. 정책 카드·공식 사이트·AI 브리핑만이면 블로그로 어렵다 | 공공 제도형(중소기업확인서)은 공식 사이트가 위. 블로그 자리가 있는지 직접 본다 |
| 경쟁도 | 마피아넷 경쟁도(여유·보통·과열), 블로그 탭 상위가 인플루언서·대형 블로그로 꽉 찼나 | 같은 검색량이면 "여유" 쪽 |
| 우리 글끼리 겹침 | 6개 블로그 posts.json 포커스와 같거나 같은 의도면 안 쓴다(카니발라이제이션) | "대학생 공모전 사이트"는 예시블로그A WP 포커스라 예시블로그A 네이버는 "디자인 공모전 사이트"(250) |
| 시기 | 신고기간·공고·시즌 키워드는 그 시기 2~4주 전에 | 간이과세자 부가세신고(1월·7월), 송년회 이벤트(11~12월) |
| 사업 가치 | 문의·구독으로 이어지는 의도면 200 미만도 WARN 감수하고 쓸 수 있다(사유를 keyword_evidence 에) | 예시블로그C "기업 출강" 190 |
| 구글 | 워드프레스와 같은 주제면 구글 검색량도 본다(volumes.mjs). 네이버 블로그 자체는 네이버 기준 | |

## 4. 기록
front matter: `head_keyword`(헤드와 검색량), `focus_keyword`, `keyword_volume`(포커스 숫자), `keyword_evidence`(후보 3개 이상과 검색량·경쟁도·SERP 판정·조회일, 고른 이유 한 줄).
