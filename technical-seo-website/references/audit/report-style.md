# 리포트 형식 (예시성형외과 SEO 기술 진단 리포트 기준)

사용자가 "테크니컬 SEO 진단의 정수"라고 한 형식이다. `scripts/audit/build_report.py`가 이 모양으로 docx를 만든다.

## 문서 구성

1. 제목: `<병원·회사명> SEO 기술 진단 리포트`
2. 부제: `전략·기획 · 백엔드·인프라 · 프론트·디자인 통합 | 진단 기간 YYYY-MM-DD ~ MM-DD | <작성 회사명>`
3. 안내문: `※ 본 진단은 Google Search Console·GA4 데이터, 사이트 전체 크롤링, 브라우저 실측, 페이지 성능 측정 결과를 기반으로 수행되었으며, 이하 항목은 사용 도구가 아닌 데이터 해석과 판정 근거 중심으로 기술함.` (실제로 쓴 데이터만 적는다)
4. 종합 표(선택): No · 항목 · 판정 · 요약 한 줄. B2C 리포트는 이 표가 본문 역할을 한다.
5. 항목 카드(번호순): 아래 구조.
6. 조치 우선순위: 문제 → 보완 순, 같은 원인끼리 묶는다(예: 22번과 32번은 같은 리디렉션 체인).

## 항목 카드 구조

```
[항목 | N. 체크항목 이름]
① 판정   ☒ ■ 문제 / ☐ ▲ 보완 / ☐ ● 정상
요약     한 문장
② 확인 내용   무엇을 어떤 범위로 확인했고 무엇이 나왔는지 + 증거 이미지
③ 진단 소견   왜 중요한지 → 지금 조건 → 고치면 성립할 조건 → 판정 문장
```

## 판정 기준

| 판정 | 기준 | 예 |
|---|---|---|
| ■ 문제 | 지금 검색 노출 손실이 발생하고 있다는 증거가 있다 | 전 페이지 동일 title, JSON-LD 0건, 소프트 404, 구글 접근 403 |
| ▲ 보완 | 당장 손실은 작지만 방치하면 손실로 이어질 수 있다 | lastmod 누락, 푸터 링크, CLS 0.44(작은 영향), 크롤 예산 재수집 편중 |
| ● 정상 | 조치가 필요 없다. 대상 기능이 없는 경우도 정상으로 두고 "대상 없음"을 밝힌다 | 필터 없음 → 정상 |

- 증거 없이 "문제"로 올리지 않는다. 확인 못 한 부분은 "확인 불가"라고 쓰고 무엇이 있으면 확인되는지 적는다(예시성형외과 49번: 예약 완료 페이지).
- 같은 원인의 항목은 하나에 흡수하고 다른 항목에는 "N번 참조"로 적는다(예시성형외과 32→22, 58→21).
- 측정 조건이 판정을 바꾸면 밝힌다(예시성형외과 24번: 국내 TTFB 0.24초 정상, 싱가포르 4G 측정은 F등급 → 해외 리전·캐시 차이로 해석).

## 문장 규칙

- 끝맺음은 "~함", "~임", "~상태임", "~로 판단함".
- **요약**: 한 문장, 수치 하나 이상. "~ 상태임"으로 끝낸다.
  - 예: `전 언어 페이지의 87~94%가 병원명 단일값을 타이틀로 사용해, 페이지별 주제 신호가 전달되지 않는 상태임.`
- **확인 내용**: "무엇을 / 어떤 범위로(전수·표본, 기간) / 무엇이 나왔나". 도구 이름보다 데이터 이름을 쓴다(크롤 데이터, 원본 HTML, 렌더링 DOM, 색인 리포트, 크롤링 통계). 예시 URL과 개수를 넣는다.
  - 예: `5개 언어 전 페이지의 원본 HTML에서 title·description 값을 전수 비교함. 5개 언어 대부분 페이지(zh-Hant 82/87·ko 86/99·ja 84/90·zh-CN 83/89)가 동일한 공통 타이틀을 쓰고 있음.`
- **진단 소견**: 네 단계를 지킨다.
  1. 원리: 구글이 이 요소를 어떻게 처리하는지 (`타이틀은 검색결과에 노출되며 구글이 페이지 주제를 판별하는 1차 신호로, …`)
  2. 현재 조건: 이 사이트에서 무엇이 어긋났는지, 개별 실수인지 템플릿 구조 문제인지
  3. 성립 조건: `…가 정비되면 …할 조건이 성립함` (결과를 약속하지 않고 조건만 말한다. 색인 시점은 재크롤 주기에 따름)
  4. 판정 문장: `현재는 …로 검색 노출 손실이 발생하는 문제로 판단함` / `당장 손실로 이어지진 않으나 … 정비가 필요한 보완 사항으로 판단함` / `… 정상으로 판단함`
- 구글 공식 입장과 다르게 오해되기 쉬운 부분은 짚는다(nofollow는 PageRank를 되돌리지 않음, FAQ 리치결과는 2026-05-07부터 구글 검색에 표시되지 않음(Search Central 업데이트 기록, 2026-10-21 확인. 서치콘솔 보고서·리치 결과 테스트 지원은 2026-06 종료), canonical은 색인 후보에서 빼주지 않음).
- 의료·YMYL은 신뢰 신호와 규제(가격 마크업 시 의료광고 규정)를 같이 언급한다.

## 증거 이미지

- 문제·보완 항목은 이미지 1장 이상. 정상 항목도 핵심 데이터 화면 1장이면 좋다(B2B).
- 화면 전체보다 판단 근거가 보이는 영역만 자른다. 개인정보·연락처·계정 메일은 가린다.
- 파일 이름: `tmp/evidence/<항목번호>-<짧은이름>-<순번>.png`.
- 원본 HTML·응답 헤더·리디렉션 체인처럼 화면이 없는 증거는 `recipes.md`의 증거 카드로 만든다(측정 URL·시각 포함).
- 이미지 바로 아래 캡션을 단다: `무엇을 / 언제 / 어디서`.

## 보고 금지

- 측정하지 않은 수치, 클라이언트 말만 있는 수치(예: "연 3억 노출")를 사실처럼 쓰지 않는다. 쓸 때는 "클라이언트 제공, 원자료 미확인"으로 표시한다.
- 원인을 단정하지 않는다. 증거가 가리키는 범위까지만 쓴다("방화벽이 구글 접근을 막는 것으로 보임").
