# 카피·디자인 규칙

예시컴퍼니 홈페이지(2026-10-13~27) 피드백에서 사용자가 확정한 것이다. 검사는 `scripts/copy-lint.mjs`.

## 1. 문체

- 사이트 전체를 합니다체로 쓴다. 짧고 자연스러운 문장으로, 사람이 쓴 것처럼 쓴다.
- 구어는 따옴표 안 고객 대사에만 쓴다. 예: "광고를 끄면 문의도 바로 끊겨요."
- 첫 화면은 슬로건이 아니라 증거와 전문성으로 시작한다.
  - H1은 회사·서비스 이름으로 짧게 쓴다.
  - H1 아래 설명은 2줄 이하로 쓴다.
  - B2B도 상대하는 회사라면 감성 카피로 열지 않는다.
- 섹션 제목은 결론을 말하는 한 문장으로 쓴다. 데이터 이름표("성과 현황")로 쓰지 않는다.

## 2. 금지 표현 → 대안

| 쓰지 않는다 | 대신 | 이유 |
|---|---|---|
| ~같이 돕니다, ~해 드립니다 남발 | ~합니다, 맡습니다 | 영업 말투 |
| 혁신적인, 완벽한, 최고의 | 구체 숫자·범위 | 근거 없는 수식 |
| 단순히 ~가 아니라 ~이다, ~하는 순간 | 바로 결론 | AI 문체 |
| ~에 대한, ~역할을 합니다, ~을 통해 | ~를 묻는, ~가 됩니다, ~로 | 번역투 |
| 효율적으로, 체계적으로, 전략적으로 | 무엇이 얼마나 줄었는지 | 컨설팅 형용사 |
| 같은 문장에 "할 수 있습니다" 여러 번 | 한 번만, 나머지는 단정 | 헤지 반복 |
| 습관적인 세 항목 나열(A, B, C) | 실제 개수대로 | AI 리듬 |
| 줄표(—) 남발, 굵은 글씨 남발 | 쉼표·문장 분리 | AI 서식 |
| PROBLEM, STEP 01 같은 영문 대문자 머리말 | 한국어 짧은 라벨("상담에서 가장 많이 듣는 말") | AI 디자인 |
| "노출도 0", "모든 게 0에서" | 제로 | 사용자 지시(10/24) |
| 어떤 업종이든 ~ 찾히게 | 네이버·구글 검색과 AI 답변에서 먼저 보이게 만듭니다 | 문장이 성립하지 않음 |

## 3. 구어 → 마케팅 용어 (10/24 사용자 지시)

| 전 | 후 |
|---|---|
| 손님이 오는 길 | 고객 여정 |
| 먼저 하는 채널 / 받쳐 주는 채널 | 핵심 채널 / 서포트 채널 |
| 업종을 고르면 손님이 오는 길과 채널 조합이 바뀝니다 | 업종을 고르면 타겟과 채널 조합이 바뀝니다 |
| 어디서 새는지 / 단계가 새면 | 이탈 지점 / 단계에서 이탈하면 |
| 들어오는 길에 따라 비용과 온도가 다릅니다 | 유입 경로에 따라 비용과 문의의 질이 다릅니다 |
| 한 벌로 맞춥니다 | 하나로 통일합니다 |
| 테크니컬 SEO가 바닥이고 | 테크니컬 SEO가 기반이고 |
| 덜어 냅니다 / 퍼뜨립니다 | 줄입니다 / 확산합니다 |
| 핸드오프는 없앴습니다 | 일을 넘기는 단계는 없앴습니다 |
| 어떻게 만드느냐 / 이때 하는 검색 | 개발 방식 비교 / 검색어 |

업계에서 실제로 쓰는 말("검색 자리", "지면")은 그대로 둔다.

## 4. 용어 통일·자기모순

- 서비스 하나에는 이름을 하나만 쓴다. 메뉴, H1, 메타, 관련 링크, 문의 폼 선택지, 푸터, 구조화 데이터 `serviceName`까지 같게 맞춘다.
  - 예시컴퍼니: "SEO 웹사이트 제작"을 "테크니컬 SEO 웹사이트 개발"로 바꿨다.
  - "기술 SEO"는 "테크니컬 SEO", "메타광고"는 "메타 광고", "진료 과목"은 "진료과목"으로 쓴다.
- 고칠 때마다 앞뒤가 맞는지 다시 본다.
  - "같은 패키지를 파는 대행사" 비판 바로 뒤에 "업종이 달라도 방법은 같습니다"가 있었다.
  - 소스 코드를 납품하지 않기로 했는데 FAQ에 "설정 파일에서 바로 바꿀 수 있게"가 남아 있었다.
  - 숫자 기준이 페이지마다 달랐다: 26·103개 점검과 80여 가지.
- 근거 없는 숫자를 쓰지 않는다. 예: "담당자는 다섯 번 검색합니다"는 "여러 번 검색합니다"로 바꾼다.

## 5. FAQ

- 계약 전에 고객이 실제로 묻는 질문으로 채운다: 비용, 순위 보장, 최소 계약 기간, 계약 후 소유권, 효과 시점, AI로 글을 쓰는지, 기존 대행사와 병행 여부, 업종별 차이.
- 답은 "됩니다"로 끝내지 않는다. 이유와 방법까지 2~3문장으로 쓴다.
- 분류 탭으로 나눈다. 화면의 질문·답과 같은 문장을 `FAQPage` 구조화 데이터에 넣는다.
- 페이지마다 그 페이지 서비스의 질문을 둔다. 메인은 대표 질문을 모은다.

## 6. 숫자·근거

- 숫자에는 출처와 측정일을 붙인다(예: "PageSpeed 데스크톱 · 2026년 10월 24일 측정").
- 실측과 추정을 나눠 쓴다. 계산기처럼 가정이 들어가면 가정값을 화면에 적는다(예: 1위 클릭률 25% 가정).
- 지어낸 후기·통계를 쓰지 않는다. 임시 수치는 "임시 수치"로 표시하고 공개 전에 지운다. 표시광고법 위험이 있다.
- 결과는 근거가 있는 큰 숫자 하나를 앞에 두고, 세부는 조용한 표(고객 / 업종 / 범위 / 기간 / 결과)로 보여 준다.
- B2C식 과장 배너는 쓰지 않는다. B2B다운 전문성을 위해 숫자는 적극적으로 쓴다.
- 사용자가 직접 정한 숫자는 근거를 확인할 때까지 고치지 않고 그대로 둔다.

## 7. 경쟁사 대비·고객사 정보

- 다른 대행사의 단점은 특정 회사가 떠오르지 않게 "흔히 보는 대행사 vs 우리"로 쓴다. 예시컴퍼니가 쓴 항목: 리포트, 블로그 글, 체험단, 같은 패키지, 이름만 바꾼 GEO.
- 고객사는 서면 동의 전까지 업종·지역으로만 표기한다(예: 안양 내과의원, 미술 콘텐츠 플랫폼). 동의를 받으면 공개 범위를 문서로 남기고, 공개 전에 고객이 미리 보게 한다.
- 검색 화면 캡처 규칙:
  - 고객사 이름·주소·썸네일·설명, 다른 사람 이름(에디터 등)을 블러로 가린다.
  - 캡처마다 엔진 배지(N·G·AI)를 단다.
  - "실제 화면" 표시와 날짜가 든 설명을 단다.
  - 챗GPT 캡처는 질문을 보이지 않게 한다.
  - 캡처 설명은 화면에 실제로 보이는 것만 쓴다. 고객 글이 나무위키와 묶여 있으면 "영상 출처"라고 쓰지 않는다.
- 병원은 의료광고 규정을 지킨다: 최상급 표현 금지, 치료 경험담·전후 사진 금지, 심의 대상 매체 확인.

## 8. 디자인

**쓰지 않는다** (사용자가 "AI가 만든 티"로 거절한 것):
- 어두운 배경에 보라 빛 번짐, 보라 그라데이션, 격자 배경
- 가운데 정렬 큰 슬로건, 한 단어만 색 바꾼 헤드라인
- 영문 대문자 머리말, 체크 표시 알약 태그
- 모든 카드 둥근 모서리, STEP 카드, 같은 모양 3칸 카드 반복
- 모든 섹션에 아래에서 올라오는 등장 효과
- 순서가 없는 내용에 01/02/03 번호

**쓴다** (예시컴퍼니 확정 방향: 스위스·에디토리얼):
- 종이색·흰 배경, 거의 검정인 글자, 1px 구분선, 각진 모서리, 왼쪽 정렬
- 강조색은 하나만, 아껴서 쓴다: CTA 점, 숫자 강조, 페이지당 한 번의 전폭 띠
- 서비스 페이지마다 구성을 다르게 짠다: 진단 리포트형(목차 고정), 대화형, 잡지형, 사양서형
- 카드 안에는 실제 데이터·화면, 설명은 카드 밖
- 높이가 다른 캡처는 세로로 쌓아 빈칸을 없앤다(CSS columns + break-inside-avoid)
- 순위표는 단순하게: "1위 / 2위 / 3위" 보드에서 1위 칸을 가장 크게
- 가치를 직접 보여 주는 상호작용은 환영한다: 검색 노출 시뮬레이터, 광고비 절감 계산기, 전후 비교 슬라이더. 내용은 서버에서 그리고 상호작용만 클라이언트로 둔다.
